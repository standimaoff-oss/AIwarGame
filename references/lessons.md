# Уроки: типовые провалы и как их ловить

Ни размеры, ни комплектация, ни стиль одного ассета не являются настройками по умолчанию для следующего. Ниже — классы ошибок, наблюдения за реальными задачами и способы их обнаружить до сдачи. Оружейный кейс с конкретикой: [lessons-pm.md](lessons-pm.md).

## Масштаб и единицы

| Наблюдение | Причина | Проверка/исправление |
|---|---|---|
| Дом оказался 4 м в высоту | Единицы сцены мм приняли за метры | Фиксировать `scale_length`, эталонная фигура 1.75 м и дверной проём в кадре на S2 |
| После экспорта объект ×100 | Разные единицы Blender/движка и неприменённый масштаб | Импорт в чистую сцену, `apply transforms`, проверка pivot и bbox |
| Персонаж выше машины | Каждый ассет моделировался в своём масштабе | Единая масштабная линейка на сцену, сверка bbox всех ассетов |
| Лестница «неудобная» | Ступени рисовали на глаз | Подъём 150–180 мм, проступь 250–300 мм, проверка вида сбоку с размерами |

## Референсы и вариант

| Наблюдение | Причина | Проверка/исправление |
|---|---|---|
| Смешаны детали двух вариантов | Референсы из разных источников усреднили | Выбрать один вариант, зафиксировать в `asset-state.md`, сверить признаки-маркеры |
| Модель повторяет несуществующую деталь | Источник — AI-изображение или чужой рендер | Ранжировать источники; AI/игровые кадры — только для общей конфигурации |
| «Сверил с фото», но расхождение осталось | Файл не открывали, судили по имени/превью | Не заявлять о сверке без просмотра изображения; сохранять ракурсы в `web_refs/` |
| Зеркальный референс перенёс асимметрию | Не отметили зеркальность источника | Для каждого источника: ракурс, зеркальность, перспектива/ортография |

## Геометрия

| Наблюдение | Причина | Проверка/исправление |
|---|---|---|
| Одна сторона красивая, сзади провал | Проверяли только общий вид 3/4 | Ортографические силуэты с 4–6 сторон на каждой стадии |
| «Плавающая» крышка обнаружилась в крайнем положении | Собранная поза прятала лишнюю грань | Проверять внутренности и нижние стороны в крайних позах |
| Проход объявлен открытым по одному лучу | Край и часть сечения перекрыты | Сетка лучей по сечению с обеих сторон + освещённый вид внутрь |
| Boolean добавил объём вместо вычитания | Solver/копланарность/незамкнутый cutter | Чистый источник, сравнение solver, триангуляция concave n-gon, контроль boundary |
| Повторная операция создала разрывы | Накопление почти совпадающих разностей | Вернуться к чистой версии и выполнить одну правильную операцию |
| Цилиндр в окне выглядел прямоугольным | Форму отверстия перенесли на видимую деталь | Смотреть саму поверхность через окно и в другом ракурсе |
| Ступени на округлой форме скрыли нормаль-мапом | Низкая сегментация | Исправить профиль и сегментацию; clay + широкий движущийся блик |
| Треугольный блик на плоскости рядом со скруглением | Интерполяция крупного n-gon | Weighted Normal (FACE_AREA, keep sharp) на копии, проверка с двух ракурсов |

## Топология и UV

| Наблюдение | Причина | Проверка/исправление |
|---|---|---|
| Сетка лопнула в позе | Петли не проходили через сустав, полюс в зоне деформации | Проверка потока рёбер, перенос полюсов, крайние позы |
| Шов виден на кромке | UV-разрез положили на видимую зону | Перенести шов, увеличить padding, проверить под бликом |
| Соседние детали разного texel density | Острова масштабировали «чтобы влезло» | checker-map и измерение см/px, единая плотность в наборе |
| Normal bake с чёрными полосами | Несовпадение hard edges и UV-швов, малый отступ | cage/extrude, совмещение швов, проверка кромок |
| Запёкся «призрак» соседней детали | Bake по всем объектам сразу | Изолировать high/low пары, mesh-name match |

## Материалы и реализм

| Наблюдение | Причина | Проверка/исправление |
|---|---|---|
| Всё выглядит как пластик | Roughness в узком диапазоне, нет вариаций | Карта roughness с вариациями, проверка гистограммы, нейтральный свет |
| Износ «везде» | Случайный шум вместо причинной логики | Размещать по контакту/воде/пыли; макро кромок и стыков |
| Следы выглядят плавающими проводами | Полосы не прилегают к изогнутой поверхности | Проецировать на evaluated surface, контролировать толщину и смещение по нормали |
| Грязь на полированной вертикальной поверхности | Нет учёта гравитации и материала | Пыль — на горизонталях, потёки — ниже источника |
| Металл там, где диэлектрик | Metallic вместо крашеного металла | Таблица PBR-значений, проверка под HDRI |
| Текстура «плывёт» на крупной стене | Неверный физический масштаб шума | Привязка масштаба к реальным размерам элемента (кирпич, доска) |

## Риг и анимация

| Наблюдение | Причина | Проверка/исправление |
|---|---|---|
| Курок/рычаг двигался неверно | Pivot у выступа, а не в точке крепления | Ось в подтверждённой точке, проверка в двух перпендикулярных ракурсах |
| Драйвер не обновился | Устаревшие зависимости в памяти процесса | Сохранить, открыть заново, `view_layer.update()` после `frame_set` |
| Предмет растёт в кадре вместо появления | Scale-ключи без CONSTANT interpolation | Дискретная видимость, отдельная интерполяция |
| Камера «прыгнула» на кадре | Camera binding/timeline markers | Явный выбор камеры после обновления кадра в диагностической серии |

## Доказательства и доставка

| Наблюдение | Причина | Проверка/исправление |
|---|---|---|
| Рендеры не соответствовали последней правке | Изображения получены раньше финальной сцены | Сохранить final candidate, открыть заново, обновить затронутые кадры |
| Инспекционный рендер «закрыл» проход | Near clip, тёмный свет, перекрытие | clip_start по масштабу, свет внутри, различимый дальний фон |
| PASS аудита приняли за качество | Конфигурация не задавала критериев | Писать конфигурацию под контракт; PASS только по перечисленным критериям |
| PR без описания, ревьюер не понял результат | Нет структуры передачи | Шаблон PR: изменения, проверки, ограничения, управление |
| Пуш отклонён: файл >100 МБ | Бинарь вне LFS | `.gitattributes` до первого коммита, `git lfs ls-files`, миграция с согласия |
| В diff попал токен | Локальный конфиг/лог закоммичен | Проверка `git diff --cached`, `.gitignore`, немедленная ротация секрета |
| Временные объекты остались в финальном файле | Инспекционная сцена сохранена поверх ассета | Финальное сохранение из чистой копии, проверка списка объектов |

## Процесс

- Не начинай детализацию до закрытых ворот формы: переделка стоит дороже, чем проверка силуэта.
- Если одна операция повторно ломает сетку — меняй подход на копии, а не повторяй её в финальном файле.
- Если правка затрагивает несколько доказательств, обновляй все затронутые, а не только одно «главное».
- Фиксируй решения: «подтверждено источником» против «предположение» — это снимает половину споров на ревью.
- Крупную задачу режь на стадии с сохранением снапшота и коммита: откат без потери работы важнее непрерывного «творческого потока».
