# Game-ready: ретопология, LOD, collision, экспорт

Выполняется только по отдельному запросу. High-poly источник сохраняется всегда до начала оптимизации и остаётся в репозитории.

## Ретопология

Цель — сетка, которая держит силуэт и материалы при малом числе полигонов, а не «упрощённый скульпт».

- Поток рёбер по формам: петли вокруг проёмов, кромок, зон деформации; quad-доминантная сетка, треугольники спрятаны на плоских и невидимых участках.
- Плотность по важности: лицо и кисти плотнее торса, видимые кромки плотнее внутренних поверхностей, крупные плоские панели свободнее.
- Ориентиры бюджета: hero-персонаж 20–80k tri, оружие 15–40k, пропс 1–10k, мебель 3–15k, автомобиль 60–150k (интерьер отдельно), здание-модуль 5–30k на модуль, дерево 3–15k, камень 1–5k, терраин — по карте высот. Конкретный бюджет всегда из задачи; эти числа — для проверки «не в разы ли больше».
- Bake high→low: cage/отступ, совпадение hard edges и UV-швов, разрешение под дистанцию, проверка артефактов по [uv-baking-maps.md](uv-baking-maps.md).

## LOD

- LOD0 — hero-вид, LOD1 −50–60% треугольников, LOD2 −75–85%, LOD3 −90% или impostor/billboard.
- Переключение не должно читаться: сохраняй силуэт и число material sets (уменьшай их только осознанно), убирай невидимые внутренности первыми, затем мелкие детали, затем плотность округлых форм.
- Экранная доля переключения согласуется с texel density: текстура 4K на объекте в 50 пикселей на экране — напрасная трата бюджета.
- Для движков с виртуализированной геометрией (Nanite) LOD не нужен, но остаётся требование чистых UV и согласованного texel density.

## Collision

- Примитивы (box/sphere/capsule) там, где форма близка к ним — дешевле и стабильнее.
- Convex hull для техники и мебели; concave/trimesh — только для статичной архитектуры и терраина.
- Имена по целевому движку: `UCX_<Mesh>_00` (Unreal), суффикс `_col`/`collision` (Unity/Godot по соглашению проекта), complex collision отдельно от визуальной сетки.
- Collision не должен повторять мелкие детали: перила, провода, декор — упрощённая оболочка; проёмы проходимы, ступени имеют подъём, соответствующий настройкам перемещения персонажа.

## Pivot, именование, иерархия

Pivot в точке установки: низ предмета для мебели/техники, центр колеса, основание здания на уровне пола/земли, точка хвата для оружия. Имена: `SM_<Asset>_<Part>` (static mesh), `SK_<Asset>` (skinned), `M_<Material>`, `T_<Asset>_<Map>_<res>`, `MT_<Material>` — или соглашение из `docs/CONVENTIONS.md` репозитория, которое имеет приоритет. Иерархия: root → узлы → детали; пустые объекты и вспомогательная геометрия удалены или исключены из экспорта.

## Экспорт

`scripts/export_asset.py` экспортирует выбранные коллекции/объекты в нужный формат с логом параметров. Ручной экспорт — с теми же проверками.

| Формат | Когда | Ключевые настройки |
|---|---|---|
| glTF 2.0 (`.glb`/`.gltf`) | веб, three.js, Babylon, Godot, Unity/Unreal | `+Y up`, метры, tangents, упакованные ORM, Draco/meshopt только если движок поддерживает, `export_apply` по согласованию, анимации и skinning включены |
| FBX | Unreal, Unity, Maya-пайплайны | масштаб 1.0, smooth groups вместо custom normals при конфликте, embed media только по запросу, bake animation при необходимости |
| OBJ | простая геометрия, CAD-просмотр, 3D-печать декора | группы по объектам, единицы в метрах, без анимаций/ригов |
| USD/USDZ | Omniverse, AR Quick Look | слои, варианты, единицы см/м по целевому пайплайну |
| STL | декоративная печать (не функциональные детали) | замкнутая manifold-сетка, масштаб в мм, стенки не тоньше 1 мм, проверка на слайсере |

Общие правила: применить трансформы там, где это требуется целевым форматом (негативный масштаб недопустим), сохранить hard edges через normals/smooth groups, проверить альфа-прозрачность и двусторонность, исключить вспомогательные объекты, камеры и свет (если движок не требует своего набора).

## Проверка экспорта

1. Импорт в чистую сцену/движок или в онлайн-вьюер glTF: масштаб (не ×100/×0.01), ориентация (up/forward), позиция pivot.
2. Материалы: все карты на месте, цветовые пространства корректны, нет «белых» или «чёрных» материалов.
3. Геометрия: силуэт совпадает с high-poly в трёх ракурсах, нет вывернутых нормалей, дыр, двойных вершин.
4. Анимация и skinning: позы воспроизводятся, нет «взрыва» весов.
5. Бюджеты: triangles, material sets, разрешения текстур, размер файла — против требований задачи.
6. `scripts/gltf_report.py` — структура, материалы, тангенты, расширения, единицы.

## Импорт в движок

Unity: `Extract Materials`/назначение вручную, sRGB флаг для BaseColor/Emissive и выключенный для data-карт, compression по платформе, `Normal Map` тип для normal, генерация mip. Unreal: `Combine Meshes` по ситуации, нормаль — OpenGL/DirectX по соглашению, collision из импортированного или простой примитив, LOD через `Auto Compute` или импорт набором, Nanite для статики по бюджету. Godot: glTF-импорт, материалы в StandardMaterial3D, UV2 для lightmap при необходимости. Three.js/веб: GLTFLoader, Draco/meshopt/KTX2 по размеру, `sRGBEncoding`/`ColorManagement`, тени и тонмаппинг по сцене.

После импорта приложи скриншот из движка в `renders/` и укажи в PR версию движка и сцену проверки.
