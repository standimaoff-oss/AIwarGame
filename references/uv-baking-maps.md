# UV, texel density, baking и наборы карт

## Texel density

Единый texel density внутри ассета и сцены — главный признак профессиональной текстурировки. Ориентиры (см/пиксель на текстуре 1024):

| Класс объекта | см/px @1024 | Комментарий |
|---|---|---|
| Hero-предмет в руках/крупный план | 2–4 | оружие, инструмент, гаджет, лицо |
| Персонаж (тело/одежда) | 4–8 | лицо плотнее, спина и внутренности свободнее |
| Мебель и пропсы среднего плана | 8–16 | |
| Архитектура, стены, крупные формы | 16–40 | часто trim/tilable карты вместо уникальных |
| Окружение, терраин, дальние объекты | 40–150 | virtual texturing / triplanar по бюджету |

Плотнее на видимых и контактных поверхностях, свободнее на скрытых (внутренности шкафа, низ мебели, тыльная сторона). Отклонение между соседними деталями больше ±30% заметно глазом.

Проверка: checker-map (квадраты 10×10 см или 1 м) — квадраты должны быть равными по всем поверхностям; измеряй фактические см/px и пиши в `asset-state.md`.

## Развёртка

- Швы прячь в невидимых и естественных местах: внутренние грани, низ, задняя сторона, стык материалов, линия шва одежды, кромка панели.
- Разрезай по реальным границам, а не «как легло»: отдельный остров на каждую самостоятельную деталь/материал.
- Hard surface: выравнивай острова по осям (straighten), сохраняй параллельность, минимизируй искажения; округлые части разрезай так, чтобы полюса не попадали на видимую зону.
- Органика: равномерное распределение площади, без «сжатых» зон у суставов; лицо — отдельный остров с максимальной плотностью.
- Отступы (padding): минимум 8–16 px для 2K, 16–32 px для 4K, чтобы mip-уровни не тянули соседний материал. Для tileable карт — бесшовность по краям с проверкой стыка 3×3.
- UDIM — когда нужна плотность без гигантских текстур (персонажи, интерьеры, транспорт); все тайлы одного material set должны быть согласованы.
- Не масштабируй UV-острова, чтобы «влезло»: сначала пересмотри разрешение и texel density.

## Наборы карт и суффиксы

Имя: `<slug>_<materialset>_<Map>_<res>.<ext>`, например `village-house_brick_BaseColor_4k.png`.

| Суффикс | Содержание | Цветовое пространство |
|---|---|---|
| `BaseColor` / `Albedo` | цвет без освещения и теней | sRGB |
| `Roughness` | шероховатость 0–1 | Non-Color |
| `Metallic` | металличность 0–1 | Non-Color |
| `Normal` / `NormalGL` / `NormalDX` | тангент-нормали | Non-Color |
| `Height` / `Displacement` | высота для displacement/parallax | Non-Color |
| `AO` | ambient occlusion | Non-Color |
| `Emissive` | свечение | sRGB |
| `Opacity` / `Alpha` / `Mask` | прозрачность, маска карточек | Non-Color |
| `Curvature` | служебная для генерации износа | Non-Color |
| `Thickness` | служебная для SSS/запекания | Non-Color |
| `Sheen` / `Anisotropy` / `IOR` | спецэффекты по движку | Non-Color |

Правила: один material set — одно разрешение для всех карт; не смешивай 2K и 4K в одном наборе; не клади AO в alpha BaseColor, если движок этого не требует (пометь в manifest, если упаковал — это стандарт glTF: ORM = Occlusion/Roughness/Metallic в RGB); нормаль — OpenGL (Y+) для Blender/Unity/Unreal, DirectX (Y−) помечай в имени и manifest.

Оптимизация под движок по запросу: упаковка ORM, исключение Metallic для диэлектриков (константа вместо карты), объединение Height в одну карту, сжатие BC7/BC5/DXT, генерация mip-цепочек.

## Baking

Порядок: high-poly источник сохранён → low-poly с cage/отступом → bake по material sets → проверка артефактов → только потом художественная доработка слоёв.

- Normal bake: достаточный отступ (extruded cage), совпадающие hard edges и UV-швы (иначе разрывы нормали), разрешение под задачу, проверка полярных зон и кромок.
- AO/curvature/thickness: из high-poly или по low-poly с учётом сцены; фиксируй радиус в реальных единицах, а не «на глаз».
- При нескольких high-poly объектах рядом используй `cage`/`mesh name`-match или отдельный bake по объектам, иначе запечётся чужая геометрия.
- Типичные артефакты: волны от недостаточного отступа, чёрные полосы на стыках hard edge, «призраки» соседних деталей, потеря мелкого рельефа при низком разрешении, инвертированная нормаль (Y-ось).
- После bake сравни рендер low-poly с текстурами и high-poly: силуэт и крупные детали должны совпадать, мелкие — читаться.

## Процедурные и рисованные текстуры

Procedural в Blender хорош для: базовых материалов, tileable поверхностей, вариаций и маскировки износа; минус — привязка к движку и сложность экспорта → запечь в карты для game-ready. Рисование в Krita/Substance-подобном слоистом файле обязательно сохраняй как исходник (`.kra`/`.sbsar`/`.psd`) со слоями Base Color, Roughness, Metallic, Normal, Height, AO и вспомогательными масками; финальные PNG не заменяют исходник.

Комбинация: процедурная база → bake → ручная доработка конкретных мест (потёк под конкретным болтом, скол на конкретной кромке) → финальные карты. Не оставляй «случайный шум» как единственный источник деталей.

## Trim sheets, decals, атласы

Для архитектуры и техники trim sheet (молдинги, кромки, профили, заклёпки) заменяет тысячи уникальных пикселей: держи единый набор trim-профилей на проект, UV привязывай к сетке trim. Decal-система (грязь, потёки, маркировки, повреждения) наносится поверх базового материала и требует отдельного канала/плоскости или проекции. Атласы для мелких пропсов — с достаточным padding и согласованным texel density.

## Экспорт текстур

- Разрешения степенями двойки (1024/2048/4096/8192), кроме UDIM-тайлов, где допустимы и нестандартные, но согласованные.
- PNG для lossless-исходников, TGA/EXR при необходимости 16 бит, JPEG — только для не критичных по качеству base color и только если так требует пайплайн.
- EXR/HDR для bake-исходников (16/32 бит), финальные карты — в формате целевого движка.
- Все карты — внутри комплекта ассета с относительными путями; в `.blend` упаковывай внешние изображения или фиксируй пути в manifest.
