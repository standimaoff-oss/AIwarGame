# Передача результата: manifest, версии, pull request

## Версии и снапшоты

- Сохраняй именованную версию **до** существенной переделки: `<slug>_v001_blockout.blend`, `_v002_form.blend`, `_v003_details.blend`, `_v004_uv.blend`, `_v005_textured.blend`, `_v006_rig.blend`.
- Рабочий файл — `source/<slug>.blend`; снапшоты сохраняй через `bpy.ops.wm.save_as_mainfile(filepath=..., copy=True)`, чтобы окно/сессия продолжали работать с основным файлом.
- Никогда не открывай другой файл в окне, которое привязано к конкретному порту/сессии пользователя: это ломает соответствие «порт → файл».
- Не накапливай неудачные Boolean, bake или слои в финальном файле: вернись к чистой версии и повтори операцию иначе.
- Предыдущие удачные версии не удаляй; в репозиторий пушь только те, что нужны пользователю (остальное — локально или в `.gitignore`).

## Manifest ассета

`assets/<slug>/manifest/asset-manifest.json` — машиночитаемое описание результата. Генерируется `scripts/make_manifest.py` (Blender, read-only) и дополняется вручную полями задачи. Схема: [templates/asset-manifest.schema.json](templates/asset-manifest.schema.json), пример: [templates/asset-manifest.json](templates/asset-manifest.json).

Обязательные блоки:

- `identity`: slug, имя ассета, архетип, вариант предмета, версия ассета, статус (`wip`/`review`/`done`).
- `units`: система осей, единицы, `scale_length`, Y-up/Z-up при экспорте.
- `dimensions_mm`: измеренный world-space bbox и что в него входит.
- `budget`: triangles (evaluated), objects, material sets, лимиты из задачи и факт.
- `collections`: дерево коллекций с типом содержимого и владельцами подвижных узлов.
- `materials`: имя, слоты, связанные изображения, packed/external, процедурные узлы.
- `textures`: файлы, карта, разрешение, цветовое пространство, лицензия/источник.
- `rig`: armature/контролы/позы/кадры, тип анимации (`staged`/`simulation`/`none`).
- `exports`: файлы, формат, опции, результат проверки импортом.
- `proofs`: рендеры с описанием, какой критерий каждый закрывает.
- `audit`: путь к отчёту, статус, число критериев PASS/FAIL/INFO/ERROR.
- `provenance`: источники референсов с лицензиями, скачанные CC0-ассеты.
- `open_items`: невыполненные пункты контракта, предположения, известные ограничения.

Manifest обновляется при каждом существенном изменении. Ручные правки не должны противоречить фактам файла: при расхождении приоритет у сгенерированных данных.

## Отчёт аудита

`audit/audit-config.json` + `audit/audit-report.json` по [audit-helper.md](audit-helper.md). Конфигурация пишется под контракт задачи: конкретные имена объектов/коллекций, ожидаемые размеры с допуском, позы, лучи для проходов. Отчёт без конфигурации — инвентаризация (INFO) и доказательством качества не является.

## Pull request

Описание PR состоит из блоков (шаблон [templates/PULL_REQUEST_TEMPLATE.md](templates/PULL_REQUEST_TEMPLATE.md)):

1. **Что сделано** — по пунктам контракта, без общих слов.
2. **Размеры и бюджет** — факт против требования.
3. **Проверки** — какие критерии закрыты и какими файлами (рендеры, аудит, texture-report, gltf-report).
4. **Доказательства** — вставленные изображения текущей версии. В описании PR используй путь от корня репозитория в markdown-синтаксисе изображения (`assets/<slug>/renders/silhouette_front.png`) или приложи скриншоты к PR: относительные пути вида `../assets/...` в описании GitHub не работают.
5. **Ограничения и предположения** — что упрощено, что принято как оценка, что не подтверждено источниками.
6. **Как открыть и управлять** — версия Blender, структура коллекций, контролы рига, как отключить demo-анимацию, где лежат исходники текстур.
7. **Связанные задачи** — `Closes #N`.

Сообщение пользователю в чате — короткая выжимка того же: изменения, проверки, ограничения, ссылка на PR. Не обещай отсутствие всех ошибок и точную реконструкцию деталей, которых не видно в источниках.

## Состав передачи

| Тип результата | Что передать |
|---|---|
| Художественный high-poly | `.blend` + исходники текстур + `textures/` + `renders/` + manifest + audit |
| Game-ready | всё выше + `exports/` (glb/fbx) + LOD + collision + `gltf-report.json` + скриншот из движка |
| Персонаж с ригом | `.blend` с armature + позы + превью движения + описание контролов + blendshape/shape keys |
| Архитектурный модуль | `.blend` + сетка привязки/размеры модуля + правила соединения + примеры собранной сцены |
| Сцена/окружение | `.blend` со scattering-коллекциями + список инстансов + tilable-доказательства + план карты |
| Только текстуры | `textures/` + исходники + tileable proof 3×3 + значения PBR в manifest |

Не переводи ассет в game-ready и не удаляй слои, UV, модификаторы или внутренние детали ради оптимизации, если пользователь этого не просил. Не отдавай только запечённые карты без исходников. Не прикладывай чужие лицензионные референсы в публичный репозиторий без разрешения — вместо этого ссылка и описание.

## Остановка работы

При команде остановиться: прекрати рендер и генерацию своих процессов (не чужие Blender-процессы пользователя), сохрани текущий файл и снапшот, обнови `asset-state.md` и manifest со статусом `wip`, закоммить и опиши состояние: что готово, что начато, что осталось. Не продолжай улучшения после команды остановки.
