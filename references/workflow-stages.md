# Стадии и ворота

Стадии идут по порядку; возвращаться назад нормально, но ворота предыдущей стадии должны оставаться закрытыми. Не начинай детализацию и материалы до закрытых ворот формы — это самая частая причина переделок.

Каждая стадия сохраняет результат в репозитории (снапшот, рендер, запись в `asset-state.md`), чтобы откат был возможен без потери работы.

## S0. Приём и контракт

- Вход: ссылка на репозиторий, issue, папка ассета, сообщение пользователя.
- Действия: клонирование, чтение задачи и существующих ассетов, определение варианта и назначения, составление карты «запрос → доказательство», инициализация структуры `assets/<slug>` (`scripts/init_asset_repo.py`), ветка.
- Выход: `TASK.md`, `asset-state.md`, ветка, пустой каркас папок.
- Ворота: известны предмет/вариант, назначение, размеры и единицы, бюджет, состав отдельных подобъектов, критерии приёмки; противоречия референсов зафиксированы.

## S1. Референсы и исследование

- Действия: сбор ракурсов (лево/право/верх/низ/перед/зад, крупные планы узлов), ранжирование источников, таблица размеров с двумя независимыми подтверждениями, скачивание CC0-текстур/HDRI при необходимости, `web_refs/sources.md`.
- Выход: папка референсов + `sources.md` + таблица размеров в `asset-state.md`.
- Ворота: каждый ключевой размер имеет источник; выбранный вариант однозначен; лицензия каждого скачанного источника записана.

## S2. Блокаут

- Действия: примитивы/крупные объёмы в реальных пропорциях, проверка силуэта с 4–6 ортографических ракурсов, масштабная линейка (человек, дверь, колесо, патрон) для сверки размера, разбиение на объекты и коллекции.
- Выход: снапшот `_v00N_blockout.blend`, clay-рендеры силуэта.
- Ворота: пропорции совпадают с референсом на силуэтных ракурсах; габариты измерены в world space и совпадают с таблицей размеров; структура коллекций соответствует составу подобъектов.

## S3. Первичная форма

- Действия: реальные профили вместо фасок на брусках, толщины оболочек, стыки и зазоры, крупные скругления, правильная сегментация округлых частей, полости и проходы (интерьер, канал, шахта, глазница, кабина).
- Выход: снапшот `_v00N_form.blend`, clay-виды с разных ракурсов, проверка проходов лучами.
- Ворота: нет видимой фасеточки на округлых частях под нейтральным бликом; проходы открыты и проверены несколькими лучами с обеих сторон; стыки читаются так же, как на референсе.

## S4. Детализация

- Действия: фаски/филлеты соразмерного радиуса, крепёж, панели, швы, насечки, профили, декор, мелкие узлы; скульпт органики (мышцы, складки, повреждения) с последующей ретопологией при необходимости.
- Выход: снапшот, макро-рендеры затронутых участков.
- Ворота: bevel непрерывный и без самопересечений; у каждой детали есть причина и принадлежность; мелкие детали не ломают силуэт; топология соответствует назначению (деформация/статика/открытая оболочка).

## S5. UV и подготовка к текстурам

- Действия: развертка по material sets, единый texel density, упаковка, straighten/выравнивание по осям для hard surface, защита швов, UDIM при необходимости; решение о ретопологии и bake в low-poly (только если заказан game-ready).
- Выход: UV-скриншоты/checker-map рендер, список material sets.
- Ворота: checker-текстура даёт равномерные квадраты без растяжений; швы спрятаны; texel density в пределах agreed cm/px; все set имеют имена и слоты материалов.

## S6. Материалы и текстуры

- Действия: base color/roughness/metallic/normal/height/AO по material sets; процедурные шейдеры и/или bake; износ, грязь, потёртости по логике контакта; decal/маркировки; emissive; ткани, кожа, стекло, растительность по правилам своего архетипа.
- Выход: `textures/` + исходники (`.kra`/node-группы), рендеры материалов при нейтральном свете.
- Ворота: значения PBR соответствуют реальному материалу; износ размещён причинно; наборы карт полны и согласованы по разрешению; цветовое пространство корректно; нет «плавающих» следов и случайного шума по всей модели.

## S7. Риг и движение (по запросу)

- Действия: иерархия и владельцы, pivot в реальных точках крепления, контролы, драйверы, для персонажа — armature/skinning/shape keys/cloth, для сцены — камеры и анимация облёта.
- Выход: риг в файле, превью движения, описание управления.
- Ворота: крайние и промежуточные позы корректны после сохранения и повторного открытия; нет самопересечений и отрыва дочерних деталей; постановочная анимация помечена как постановочная.

## S8. Доказательства

- Действия: полный набор ракурсов под конкретные правки (clay, силуэт, макро, интерьер/полости, turntable, сравнение с референсом, кадры поз), финальный художественный рендер, скриптовый аудит.
- Выход: `renders/` + `audit/audit-report.json` + `manifest/asset-manifest.json`.
- Ворота: каждое изображение соответствует текущей версии файла; каждый пункт контракта имеет свидетельство; аудит не содержит FAIL по заданным критериям.

## S9. Game-ready (по запросу)

- Действия: ретопология, bake high→low, LOD, collision, атласы/trim, экспорт в целевой формат, проверка импортом в чистую сцену или целевой движок.
- Выход: `exports/` + `gltf-report.json` + скриншоты из движка/вьюера.
- Ворота: high-poly источник сохранён и не разрушен; экспорт открывается, масштаб и ориентация верны; материалы, hard edges, прозрачность и анимации перенеслись; бюджеты соблюдены.

## S10. Доставка

- Действия: обновление `asset-state.md` и manifest, коммиты, пуш ветки, PR с описанием и доказательствами, ссылка issue, релиз при необходимости.
- Выход: PR + краткий отчёт пользователю: что сделано, чем доказано, ограничения, как управлять.
- Ворота: в репозитории нет секретов и мусора; LFS-файлы скачиваются в чистой копии; описание PR соответствует фактическому состоянию; невыполненные пункты контракта названы явно.

## Типичные провалы стадий

| Стадия | Провал | Как поймать |
|---|---|---|
| S2 | «Похоже» на одном красивом ракурсе | ортографические силуэты с 4–6 сторон + масштабная линейка |
| S3 | Пустой shell вместо интерьера/канала | вид внутрь, лучи по сечению, снятая крыша/разрез |
| S4 | Bevel по всей модели вместо исправленного профиля | clay + широкий движущийся блик, макро кромки |
| S5 | Разный texel density у соседних деталей | checker-map и измерение cm/px по объектам |
| S6 | Износ «везде» и грязь без причины | макро на кромках/стыках, сравнение с фото реального предмета |
| S7 | Поза ломается после переоткрытия файла | проверка в новом процессе, а не в сессии-создателе |
| S8 | Рендеры старой версии выданы за текущие | сверка времени файла и снапшота, рендер из переоткрытого final candidate |
| S10 | Бинарь в 300 МБ без LFS | `git lfs ls-files`, проверка CI, `git count-objects -vH` |
