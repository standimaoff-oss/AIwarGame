# Окружение: инструменты, пути, коннекторы

Окружение определяется по факту, а не по примерам этого файла. Пример записанного выбора пользователя: на 30 сентября 2026 выбран `D:\ПРОГРАММЫ\Blender 5\blender.exe`, исполняемый файл сообщал Blender 5.2.2 LTS. Перед работой проверь наличие и текущую версию, сохраняя выбор пользователя. Не подменяй его другой установленной версией только потому, что она первой нашлась в PATH.

Если Blender-коннектор доступен, сначала выясни состояние подключения и активного файла. Во время работы над ПМ коннектор не подключался; правки выполнялись фоновым Blender и сохранялись отдельной версией. Это наблюдение не означает, что коннектор всегда отключён. Не обещай изменение живой сцены, если редактировался только файл.

Для отдельного фонового процесса полезен `--factory-startup`: он избегает влияния пользовательских startup addons, не меняя настройки Blender пользователя. Сохраняй модель в текущем проекте; старый каталог ПМ не является общим местом для всех новых ассетов.

Пример проверки версии в PowerShell:

```powershell
& 'D:\ПРОГРАММЫ\Blender 5\blender.exe' --version
```

JSON-аудит запускается встроенным Python Blender и не требует установки пакетов. В окружении ПМ также были `D:\whisper\ffmpeg\bin\ffmpeg.exe` и `D:\whisper\ffmpeg\bin\ffprobe.exe`; проверяй их наличие перед использованием для запрошенного ролика.
Русскоязычные исходники и JSON сохраняй в UTF-8. Для внешних Python-утилит, использующих системную кодировку Windows, запускай `python -X utf8`; в собственных чтениях/записях задавай `encoding='utf-8'`.

Держи журналы и временные рендеры в рабочей папке текущей задачи. Не останавливай другие Blender-процессы пользователя: при остановке работы заверши только процессы, запущенные для этой задачи.

## Инструменты конвейера

Проверь наличие и версии до работы, сохрани выбор пользователя и не подменяй его версию инструмента на первую найденную в PATH:

- **Blender** (4.2 LTS / 5.x LTS): геометрия, материалы, bake, рендер, экспорт. API меняется между версиями: `bpy.types.Scene.render.engine` имеет разные имена EEVEE (`BLENDER_EEVEE` до 4.1, `BLENDER_EEVEE_NEXT` в 4.2+, `BLENDER_EEVEE` снова в 5.x), часть операторов UV/бейка переименована. Определяй версию в рантайме и выбирай ветку кода, а не пиши имя движка жёстко.
- **GPU**: OptiX (NVIDIA), HIP (AMD), Metal (Apple) + denoiser для Cycles. Для диагностических серий — EEVEE/Workbench, для финала — Cycles.
- **Python 3.9+** (системный, не встроенный в Blender) — для `validate_asset.py`, `texture_report.py`, `gltf_report.py`, `init_asset_repo.py`.
- **git + GitHub CLI (`gh`) + git-lfs**: `git lfs version`, `git lfs install --local`, `gh auth status`. Без LFS бинари больше 50–100 МБ блокируются GitHub.
- **ffmpeg/ffprobe**: кодирование превью анимации; проверяй наличие перед обещанием ролика.
- **Krita / Substance-подобный редактор**: слоистые исходники текстур; финальные PNG не заменяют исходник.
- **node/npm** — только если в репозитории есть веб-вьюер для проверки glTF (three.js, Babylon sandbox); не устанавливай пакеты без необходимости.

## Коннекторы и MCP

Если Blender-коннектор/MCP доступен, сначала выясни состояние подключения, активный файл и версию протокола. Во время работы над ПМ коннектор не подключался; правки выполнялись фоновым Blender и сохранялись отдельной версией — это наблюдение, а не правило: коннектор не всегда отключён. Не обещай изменение живой сцены, если редактировался только файл.

При нескольких открытых сессиях/портах сверяй `bpy.data.filepath` с ожидаемым файлом перед каждой правкой и каждым сохранением; не открывай другие файлы в этих окнах; сохраняй снапшоты через `save_as_mainfile(..., copy=True)`. При устаревшем MCP-аддоне откатывайся на `execute_blender_code`, не переустанавливай аддон и не перезапускай Blender без согласия пользователя. Длинные скрипты режь на шаги, чтобы не упереться в таймаут, и печатай результат каждого шага.

## Пути и кодировки

Пути конкретного компьютера (Windows `D:\ПРОГРАММЫ\...`, `W:\...`) — примеры, а не значения по умолчанию: определяй окружение по факту и пиши фактические пути в `asset-state.md`. Русскоязычные исходники и JSON сохраняй в UTF-8; для внешних Python-утилит, использующих системную кодировку Windows, запускай `python -X utf8`; в собственных чтениях/записях задавай `encoding='utf-8'`. Кириллицу и пробелы в именах файлов ассетов избегай: они ломают LFS, CI и часть движков.

Журналы и временные рендеры держи в рабочей папке текущей задачи и не коммить их без необходимости. Не останавливай другие Blender-процессы пользователя: при остановке работы заверши только процессы, запущенные для этой задачи.
